== General Component Communication

All inter-component communication is carried out using JSON messages.
This communication occurs either through direct REST interactions from the frontend to the BFF (backend for frontend), or for inter-service communication, an AMQP messaging queue via a broker instance, as provided by https://www.rabbitmq.com/[RabbitMQ].

== Transaction related schemes and definitions

This Chapter outlines all available APIs in the following Order:

1. The Backend which accepts AMQP messages related to the process.
2. The API exposed through the BFF which the {projectName} Frontend uses to query for data.

=== AMQP specific messaging interfaces and API

The General SVC and Process SVC allow the following AMQP endpoints.

==== Company API
|===
| *Company Controller* | Path | Description
| READ | `company.read` | Read all company details
|===


==== Power Purchase Agreement API
|===
| *Power Purchase Agreement Controller* | Path | Description
| READ | `power-purchase-agreement.read` | Read all power purchase agreements
| CREATE | `power-purchase-agreement.create` | Create a new power purchase agreement
| UPDATE | `power-purchase-agreement.update` | Update the status of a certain power purchase agreement
| READ_APPROVED_GRID_POWER_PRODUCTION_UNIT_BY_USER_ID | `power-purchase-agreement.read-approved-grid-power-production-unit-by-user-id` | Read all power purchase agreements that have been approved
|===

==== Process Step API
|===
| *Process Step Controller* | Path | Description
| CREATE_PROCESS_STEP | `process-step.create-process-step` | Create a new process step with the given payload
| READ_ALL_BY_TYPES_AND_ACTIVE_AND_OWNER | `process-step.read-all-by-types-and-active-and-owner` | Read all process steps with a certain type that are active and where the logged in user is the owner
| READ_ALL_BY_UNITS | `process-step.read-all-by-units` | Read all process steps that were executed by a certain unit
| READ_PRODUCTION_PAGINATION | `process-step.read-pagination-by-predecessor-types-and-owner` | Read all H2 production process steps and return them paginated
| READ_PROCESS_STEP_PAGINATION | `process-step.read-pagination-by-filter` | Read all process steps and return them paginated

==== Production API
|===
| *Production Controller* | Path | Description
| CREATE | `production.create` | Create a new Production
| ASSEMBLE_PRODUCTION_STATISTICS | `production.assemble-production-statistics` | Return the statistics for the stored productions 
| STAGE | `production.stage` | Create new staged production
| FINALIZE | `production.finalize` | Remove two staged productions and create a new production
| READ_CSV_DOCUMENTS_BY_COMPANY | `production.read-csv-documents-by-company` | Read the stored csv documents
| READ_STAGED_PRODUCTION_BY_COMPANY | `production.read-staged-productions-by-company` | Read the staged production for a certain company
| VERIFY_CSV_DOCUMENT_INTEGRITY | `production.verify-csv-document-integrity` | Verify a certain csv document with the hash stored on the blockchain
|===

=== REST specific messaging interfaces and API

The BFF serves as a bridge for the frontend and enables RESTful endpoints.
Once the BFF service has been launched, the Swagger documentation (OpenAPI) is available at `http://<bff-host>:3000/api/`.
